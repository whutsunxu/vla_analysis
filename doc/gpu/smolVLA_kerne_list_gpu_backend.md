| Compute path | Precision | Peak throughput | Physical intensity (FLOPs/byte) |
|---|---|---|---:|

| DRAM | GDDR7 | **448 GB/s** | — (bandwidth only) |

Physical intensity (ridge point) = `Peak FLOP/s ÷ Peak DRAM BW` = `TFLOP/s ÷ 0.448` with DRAM = **448 GB/s**. Ops with arithmetic intensity below this ridge are DRAM-bound vs that compute path; above it are compute-bound.

\* Some docs list packed CUDA BF16 as 2× FP32 (~47 TFLOP/s → physical intensity ~**104.9**); consumer sheets often quote ≈ FP32.

**Roofline use with this doc:** compare BF16 CUTLASS/Flash GEMMs to **94.8 TFLOP/s** dense TC (ridge **~211.6** FLOPs/byte; PyTorch path here does **not** use 2:4 sparsity). Compare FP32 SIMT/cuBLASLt/MAGMA GEMMs to **23.7 TFLOP/s** CUDA (ridge **52.9**). Compare copy/cast and low–arithmetic-intensity elementwise to **448 GB/s**. Peaks assume sustained boost; boards may clock lower under power/thermal limits. NVIDIA “AI TOPS” marketing (e.g. 759) is a different sparse low-precision metric — not the BF16 dense peak above.

### 0.2 Theoretical bottleneck analysis (table column)

Stage tables report **IO Volume /GB**, **BD /GB/s**, **BD util ratio**, **GFLOPs**, **GFLOPs/sec**, **FLOPs util ratio**, **Arithmetic intensity (FLOP/byte)**, and **Theoretical bottleneck**. Bottleneck labels are **not** taken from measured CUPTI time; they are a **roofline latency estimate** from algorithmic work vs §0.1 peaks. **BD** / **GFLOPs/sec** / util columns use measured CUPTI **GPU time per launch**.

#### Quantities

| Symbol | Definition |
|---|---|
| **IO Volume** | Σ bytes(all listed inputs) + Σ bytes(output) |
| **2D FLOPs** | Matmul / conv MAC work (`2 × K × M × N` style; BF16 or FP32 as tagged) |
| **1D FLOPs** | Bias add, or an explicit 1D epilogue (e.g. Softmax, attn score `÷√d`) |
| **Unmarked FLOPs** | Elementwise / reduce / LN helpers with no 2D–1D split |
| **AI** | `FLOPs ÷ IO_bytes` (≡ GFLOPs ÷ IO Volume/GB); if both 2D and 1D exist, AI is shown **per component** on the **same** IO |
| **BD** | `IO Volume /GB ÷ GPU_time` → **GB/s** (CUPTI launch time) |
| **BD util ratio** | `BD ÷ 448 GB/s` (§0.1 DRAM peak), shown as %. If **≥100%**, cell is tagged `⚠…` with a likely cause (not real DRAM > peak) |
| **⚠ BD≥100% tags** | `fill/algo-IO≠DRAM` — Fill byte model ≫ actual DRAM writes; `inferred-oversize-IO` — *[no aten]* Cast/Copy inherited a too-large shape; `launch-floor+algo-IO≠DRAM` — CUPTI time ≲1.5 µs vs multi-MB model IO; `L2/cache·algo-IO≠DRAM` — working set served from L2/RF, algorithmic IO assumed DRAM |
| **GFLOPs/sec** | `GFLOPs ÷ GPU_time` (if cell is `2D + 1D`, sum both) |
| **FLOPs util ratio** | `(GFLOPs/sec) ÷ peak`; peak = **94.8 TFLOP/s** for **2D BF16** (TC), else **23.7 TFLOP/s** (CUDA / 1D / unmarked). Shown as %. Zero-FLOP rows: — |

**When 1D is counted:** only if the op really has bias (Aten `+ bias` / `× [N]` bias vector) or an explicit 1D epilogue. Bias-free Linears (ViT attn-out & MLP, all Stage 2/3 Linears) are **2D only**. Patch Conv bias is the following `Add (conv bias)` row, not folded into the conv’s 1D.

#### Latency model (choose the longest)

Using §0.1 peaks:

| Path | Peak used |
|---|---|
| **2D BF16** (TC GEMM / conv / Flash math) | **94.8 TFLOP/s** |
| **2D FP32** (SIMT / MAGMA / cuBLASLt FP32) | **23.7 TFLOP/s** |
| **1D** / unmarked elementwise (any dtype here) | **23.7 TFLOP/s** (CUDA vector) |
| **DRAM** | **448 GB/s** |

```text
time_2D  = 2D_FLOPs   / peak_2D          # 0 if no 2D term
time_1D  = 1D_FLOPs   / peak_1D          # 0 if no 1D term
time_calc = unmarked_FLOPs / peak_1D     # elementwise-only rows
time_bd  = IO_bytes   / 448e9
```

**Theoretical bottleneck** = label of `max(time_2D, time_1D, time_calc, time_bd)`:

| Winner | Label |
|---|---|
| `time_2D` | `2D-calc-bounded` |
| `time_1D` | `1D-calc-bounded` |
| `time_calc` (no 2D/1D split) | `calc-bounded` |
| `time_bd` | `bd-bounded` |

On exact ties, prefer `2D-calc-bounded` > `1D-calc-bounded` > `calc-bounded` > `bd-bounded`.

#### Example (ViT Q Linear, with bias)

`2D ≈ 1.208×10⁹` BF16 FLOPs, `1D ≈ 7.86×10⁵` BF16 FLOPs, `IO ≈ 4.33×10⁶` B:

| Term | Latency |
|---|---:|
| `time_2D` | 1.208e9 / 94.8e12 ≈ **12.7 µs** |
| `time_1D` | 7.86e5 / 23.7e12 ≈ **0.03 µs** |
| `time_bd` | 4.33e6 / 448e9 ≈ **9.7 µs** |

→ **`2D-calc-bounded`** (`time_2D` longest). Prefill Q (bias-free, smaller AI) often flips to **`bd-bounded`** because `time_bd > time_2D`.

#### Limits

- Algorithmic FLOPs / full tensor IO — ignores L2 hits, epilogue fusion inside the kernel, and clock below boost.
- FlashAttention’s 1D term is a Softmax/scale **model**, not a separate launch.
- Measured **GPU time per launch** (CUPTI) can disagree with these ideal times; use CUPTI for latency, this column for **bound type**.
- **BD util ≥100%** (`⚠…` on the BD util cell): algorithmic IO ÷ CUPTI time exceeds DRAM peak — almost always **over-counted IO** and/or **L2 hits** / **launch floor**, not super-DRAM hardware.

### 9.2 Family notes

#### Convolution
Single Patch Conv dominates Stage‑0 prepare time among templates (**~199 µs**, AI≈279 → 2D-calc-bounded) but only **~6%** of BF16 TC peak — large theoretical headroom if the implementation or autotuning improves; not a DRAM story.

#### Linear
Clear **size / AI split**:
- **ViT** (M=1024): 2D-calc-bounded, **~40%** TC util — healthiest Linears.
- **Prefill / expert** (M=241 or 50): bd-bounded, **~10–37%** TC — weight traffic dominates.
- **Expert Cross-K/V**: FP32 `simt_sgemm` on prefix 241, **~13%** of CUDA peak and **~15 µs** each — top odd-layer hotspots; prefer bf16 TC or fuse into cross-attn.

#### MatMul vs fused attention
Eager `QKᵀ`/`A·V` (+ `where` + Softmax) are **bd-bounded** at **~4–22%** FLOPs util. ViT **Flash** is **2D-calc-bounded** at **~42%** TC util. Largest Stage‑2/3 win: **eager → SDPA/Flash** (also drops Softmax/where launches).

#### Softmax
FLOPs util negligible; BD util >100% = algo-IO / L2 (§0.2 ⚠). Treat as fusion fodder, not a bandwidth-tuning target.

#### RMSNorm vs LayerNorm
RMSNorm = many launches, ≪1% FLOPs util, often ⚠ BD. LayerNorm = fused, still bd-bounded at ~3% FLOPs / ~86% BD model. Prefer **one fused RMSNorm** matching the ViT LN pattern.

### 9.3 Priority reading (perf potential)

| Priority | Action | Why (from this capture) |
|---|---|---|
| **P0** | Stage 2/3 eager attn → Flash/SDPA | Flash already **~42%** TC & 2D-bound; eager matmul/softmax are bd-bound & fragmented |
| **P0** | Fuse RMSNorm chains | Dozens of sub‑µs–few‑µs launches; ViT LN shows fused is available |
| **P1** | Expert Cross-K/V off FP32 SIMT | ~15 µs ×2 / odd layer at ~13% CUDA; odd `A·V` FP32 similar |
| **P1** | SwiGLU / residual epilogues on MLP Linears | Prefill/expert MLP already mid util but still bd-bound + separate SiLU/mul |
| **P2** | Patch Conv algorithm / fusion | Longest single template launch but only ~6% TC — worth tuning if Stage 0 wall matters |
| **P2** | Pack QKV Linears | Three similar GEMMs per layer (ViT/prefill/expert) |

### 9.4 How to read util here

- **High FLOPs util + 2D-calc-bounded** (ViT Linear / Flash) → compute-limited; optimize algo / fusion / occupancy.
- **Low–mid FLOPs util + bd-bounded** (expert Linear, eager matmul) → feed more math per byte (fuse, longer effective K, fewer launches) or cut traffic.
- **BD util ≥100%** on Softmax/RMS/cast → **ignore as DRAM util**; fix the IO model or fuse — see ⚠ tags in tables.

## 10. Skill — produce a GPU kernel list for any inference path

This section is the **playbook** used to build *this* file (`smolVLA_kerne_list_gpu_backend.md`). Pair it with the AtenOp skill (`SmolVLA_AtenOp_List_gpu_backend.md` **§7**): ATen chrono = *what PyTorch called*; this doc = *what the GPU ran*, with per-launch times and roofline metrics.

### 10.1 Goal and deliverables

| Deliverable | Content |
|---|---|
| **`.nsys-rep` (+ sqlite)** | Nsight Systems capture of one steady-state inference chunk |
| **Stage duration table** | Wall-span, busy Σ, gap ratio, launch count, relative time window |
| **Kernel tables (first template only)** | Per-launch: operator label, I/O shapes/dtypes, IO/BD/GFLOPs metrics, bottleneck, CUPTI µs, full demangled kernel |
| **Platform §** | Peak TFLOP/s + DRAM GB/s for the capture GPU (roofline denominators) |

**In scope:** CUPTI kernel launches in order; algorithmic IO/FLOPs; measured util vs peaks.  
**Out of scope:** replacing ATen chrono (build that first or in parallel); using CSV `cuda_gpu_kern_sum` averages as per-launch times.

### 10.2 Prerequisites

1. **AtenOp inventory** (recommended) — same stages/templates as `*_AtenOp_List_gpu_backend.md` / `*_aten_chrono.json` for shape/dtype matching.
2. **Nsight Systems** on the target machine (this capture: **2025.1.3**).
3. **Eager CUDA inference** target that can run between `cudaProfilerStart` / `Stop` (this repo: `src/smolvla_nsight_target.py`).
4. **GPU peak sheet** for §0.1-style table (SM count, DRAM GB/s, BF16 TC / FP32 CUDA peaks at boost).

### 10.3 Step-by-step (SmolVLA → generalize)

#### Step 1 — Capture one steady-state chunk with Nsight

Warmup **outside** the profiler range; measure **one** (or few) chunk(s) inside:

```bash
# Pattern used for this file (paths may differ on host)
nsys profile -o doc/gpu/nsight/smolvla_nsys \
  --capture-range=cudaProfilerApi --capture-range-end=stop \
  python src/smolvla_nsight_target.py
# NSIGHT_WARMUP=2 (or 3), NSIGHT_REPEATS=1 inside the target
```

Requirements:

- Same model / batch / seed as the Aten chrono when possible.
- `torch.inference_mode()`, no `torch.compile` / CUDA graphs unless that *is* the product path.
- After capture: keep the `.nsys-rep`; export sqlite for queries.

#### Step 2 — Export CUPTI kernels (not CSV averages)

```bash
nsys export --type=sqlite -o doc/gpu/nsight/smolvla_nsys.sqlite \
  doc/gpu/nsight/smolvla_nsys.nsys-rep
```

Query table **`CUPTI_ACTIVITY_KIND_KERNEL`** joined to **`StringIds`** on `demangledName`:

| Field | Use |
|---|---|
| `start`, `end` | ns timestamps → GPU time `(end-start)/1000` µs |
| `demangledName` | **Full** kernel string in the Kernel column |
| Order by `start` | Chronological launch list |

Optional: generate `cuda_gpu_kern_sum.csv` for overview — **do not** use its Avg as the table’s “GPU time per launch” (this doc uses per-instance CUPTI).

#### Step 3 — Pick the measured chunk and set `t0`

1. Find the first kernel of interest (e.g. first `upsample` / first stage marker).
2. Set `t0 = MIN(start)` over all CUPTI kernels (or document another origin).
3. Report times as **ms relative to `t0`**.
4. If the report contains multiple inferences, choose the **steady** one (here: chunk whose upsample sits at **540.4229 ms** after 2 warmups).

#### Step 4 — Map stage windows (wall + busy)

Align CUDA timeline to the same stages as AtenOp §7:

| Approach | How |
|---|---|
| **Landmark kernels** | e.g. first patch/upsample → Stage 0; first prefill Q GEMM → Stage 2; three even QKV wmms → Stage 3 even; `simt_sgemm` Cross-K/V → Stage 3 odd |
| **Aten fingerprints** | Match shapes: Softmax `(int)9` → K≈291 even; `(int)8` → K≈241 odd/prefill; FP32 Cross-K vs bf16 A·V |
| **Wall-span** | `last_end − first_start` in the stage window |
| **Busy Σ** | Σ `(end-start)` of launches in the window |
| **Gap ratio** | `(wall − busy) / wall` — note overlapping Euler stages inflate gaps |

Fill a §1-style stage duration table for the whole chunk, then zoom to **first template** windows for detailed tables.

#### Step 5 — Extract the first template’s launches

For each stage, keep only the **first** repeated unit (first ViT block, first prefill layer, first even expert, first odd expert, …):

1. Bound `[t_start, t_end)` with landmarks (and fix boundaries when the next layer’s RMSNorm was glued onto the previous — as with even→odd).
2. Dump every CUPTI kernel in order with µs.
3. Count launches and busy Σ for the blurb line.

#### Step 6 — Label operators and match ATen I/O

Walk launches in order alongside the Aten template:

| Kernel signal | Typical label |
|---|---|
| `wmma` / `s16816gemm` / `implicit_convolve` | Linear / Conv (match Aten `linear`/`conv2d` shapes) |
| `magma_sgemmEx` / `simt_sgemm` | Attn `QKᵀ` or `A·V` (dtype from template args) |
| `flash_fwd` | Fused SDPA |
| `softmax_warp_forward<(int)N>` | Softmax; `N` encodes key-length class |
| `pow`+`MeanOps`+`rsqrt` cluster | RMSNorm |
| `sin_kernel`/`cos_kernel` + arange/pow | RoPE |
| `BinaryFunctor` Mul/Add, `direct_copy`, `FillFunctor` | Elementwise / cast / fill → often `*[no aten]*` |

Rules:

- Prefer **Aten shapes/dtypes** when seq order matches.
- Else infer from functor + neighbors; tag **`*[no aten]*`** and `(inferred)` I/O.
- If demangled dtype ≠ Aten dtype, mark **`[dtype≠aten]`** and size IO from the **kernel** dtype.
- Keep the **full** demangled name in the Kernel column.

#### Step 7 — Fill IO / GFLOPs / AI / Theoretical bottleneck

Use §0.2:

1. **IO Volume** = Σ bytes(inputs) + bytes(output) from the I/O column.
2. **2D FLOPs** = `2×M×K×N` (and batch) for GEMM/conv; tag BF16 vs FP32.
3. **1D FLOPs** only for real bias or explicit epilogues (Softmax, score `÷√d`) — not bias-free Linears.
4. **AI** = FLOPs / IO_bytes.
5. **Theoretical bottleneck** = argmax of `time_2D`, `time_1D`, `time_calc`, `time_bd` vs §0.1 peaks (not vs CUPTI time).

#### Step 8 — Add measured BD / GFLOPs util columns

Using CUPTI GPU time `t`:

| Column | Formula |
|---|---|
| **BD** | `IO_GB / t` → GB/s |
| **BD util** | `BD / DRAM_peak` (here 448 GB/s), as % |
| **GFLOPs/sec** | `GFLOPs / t` (sum 2D+1D if both present) |
| **FLOPs util** | `(GFLOPs/sec) / peak`; peak = BF16 TC for **2D BF16**, else CUDA peak |

If **BD util ≥ 100%**, tag the cell with a likely cause (`⚠L2/cache·algo-IO≠DRAM`, `⚠inferred-oversize-IO`, `⚠launch-floor+algo-IO≠DRAM`, `⚠fill/algo-IO≠DRAM`) — see §0.2. Do not treat it as real DRAM > peak.

#### Step 9 — Write the markdown and freeze artifacts

Document structure (this file’s layout):

1. §0 Source + platform peaks + metric definitions  
2. §1 Stage durations (full chunk)  
3. §2… kernel tables for each **first** template  
4. §10 this skill  

Check in / publish: `.nsys-rep`, sqlite (or export recipe), kernel-list md, link to AtenOp list + chrono JSON.

### 10.4 Checklist for a new inference case

- [ ] AtenOp stages/templates available (or build in parallel per AtenOp §7)  
- [ ] Nsight profile with warmup outside `cudaProfilerStart/Stop`  
- [ ] `nsys export` sqlite; query `CUPTI_ACTIVITY_KIND_KERNEL`  
- [ ] `t0` + measured chunk chosen; relative ms windows recorded  
- [ ] Stage wall/busy/gap table filled; Euler overlap noted if any  
- [ ] First-template bounds fixed (no stolen next-layer RMSNorm)  
- [ ] Each launch labeled; Aten-matched vs `*[no aten]*` / `[dtype≠aten]`  
- [ ] IO / 2D / 1D / AI / theoretical bottleneck per §0.2  
- [ ] BD + FLOPs util from CUPTI time; ⚠ tags on BD util ≥100%  
- [ ] Platform peaks documented for *this* GPU  
- [ ] Full demangled kernel strings retained  

### 10.5 What to copy vs rewrite

| Keep as-is (skill) | Rewrite per model / GPU |
|---|---|
| CUPTI per-launch timing; ignore kern_sum Avg for tables | Capture command, warmup/repeat counts |
| Column layout + §0.2 bottleneck / util math | Landmark kernels, stage windows, templates |
| `*[no aten]*` / `[dtype≠aten]` / ⚠ BD tags | Peak TFLOP/s and DRAM GB/s (§0.1) |
| Pair with Aten chrono for I/O | Aten shapes, even/odd (or other) fingerprints |

### 10.6 Minimal adapter sketch (other model)

```text
1) nsys profile --capture-range=cudaProfilerApi -- your_infer_target.py
2) nsys export --type=sqlite → query CUPTI kernels ordered by start
3) Align windows to your AtenOp stages (landmarks + shapes)
4) For each first template:
     for kernel in window:
       label ← match Aten or infer *[no aten]*
       IO, FLOPs ← shapes; bottleneck ← §0.2
       BD, utils ← IO/FLOPs ÷ CUPTI_time vs peaks
5) Emit markdown tables + stage duration summary
```

**Bottom line:** Nsight CUPTI launches in order → stage windows → first-template tables, with I/O from Aten (or inferred) and roofline + measured util vs the capture GPU’s peaks — that is how this SmolVLA kernel list was produced and how to reproduce it for another inference stack.
